# DevForge implementation blueprint

## Product contract
A native Windows CLI that generates and operates a Docker-first Go, Java 21, Python and Redis workspace. The CLI runs on Windows; all development runtimes run in Linux containers.

## Commands
- `init`: interactive workspace creation; refuses to overwrite an existing devforge.yaml.
- `install`: guided winget installation of Git and Docker Desktop, with consent.
- `doctor`: validates Docker CLI, Compose and Linux engine.
- `generate [--force]`: generates missing files; preserves existing files by default.
- `up`, `down`, `watch`, `logs`: Compose lifecycle.
- `test`: runs enabled language test runners, continues after individual suite failures, returns nonzero if any suite fails.
- `security [--image IMAGE]`: Trivy filesystem scan and optional image scan.
- `report`: creates a consolidated HTML report from JUnit XML and Trivy JSON.
- `clean [--volumes]`: removes containers; named volumes require explicit flag and typed confirmation.

## Components
- Cobra + Huh: CLI and interactive wizard.
- YAML: workspace configuration.
- Go embed: versioned project templates.
- Docker Compose Watch: source synchronization.
- Air: Go rebuild/restart.
- Maven + Spring Boot DevTools: Java service; Compose Watch sync+restart reruns Maven compile.
- Uvicorn reload: Python service.
- gotestsum, Maven Surefire/JaCoCo, pytest-cov: test/coverage artifacts.
- Trivy: filesystem and optional image scans.
- Standard-library Go report aggregator: JUnit XML + Trivy JSON to HTML.

## Reliability and security
- Do not mount Docker socket into workload containers.
- Never use privileged containers.
- Preserve volumes by default.
- Use named volumes for Redis and dependency caches.
- Do not put credentials in generated Compose files.
- Use explicit image tags, not latest.
- Keep generated files non-destructive by default.
- Require typed confirmation before deleting volumes.
- Use context cancellation and command timeouts for long-running operations.
- Validate on Windows paths containing spaces and non-ASCII characters.

## Current implementation boundaries
The installer invokes winget but does not self-elevate or reboot the machine. Docker Desktop must be started manually and configured for Linux containers. Java Compose Watch uses sync+restart so Maven recompiles on source edits. Report aggregation summarizes nested JUnit XML, language coverage artifacts and Trivy severity totals. SARIF files are retained for code-scanning integrations; they are not rendered as a full finding-by-finding table in the HTML page. Go JUnit XML is generated by gotestsum. Integration test scaffolding is intentionally omitted until project-specific integration contracts exist.

## Acceptance tests
1. `devforge init` creates a starter workspace without overwriting existing configuration.
2. `devforge doctor` catches missing CLI, Compose and daemon.
3. `devforge up` starts selected apps and Redis with health check.
4. Edits to Go, Java and Python trigger their reload/restart mechanisms.
5. `devforge test` runs all selected suites and continues after failures.
6. `devforge report` generates reports/html/index.html even when some report types are absent.
7. `devforge security` writes JSON and SARIF artifacts.
8. `devforge down` preserves Redis data.
9. `devforge clean --volumes` requires typed confirmation.
10. `devforge generate` preserves user edits unless `--force` is passed.
